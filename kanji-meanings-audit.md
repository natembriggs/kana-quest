# Kanji meanings audit — truncated meanings lists

Status: **audit complete, 2026-09-24, no fix applied yet.** Triggered by a
live bug report: 調's detail screen showed meanings `tune, tone, meter, key
(music)` with no mention of "investigate" — despite the screen's own example
words (調べ/調査 "investigation", しらべる "to examine") being built entirely
around that sense.

## Root cause

`src/data/kanji-grade-*.js` is generated by `tools/build_kanji_data.py` from
KANJIDIC2. `parse_kanjidic()` hard-truncates every kanji's meanings to the
first 4 non-radical entries **in KANJIDIC2's own raw order**:

```python
"meanings": [m for m in meanings if not RADICAL_MEANING.search(m)][:4],
```

KANJIDIC's meaning order isn't by frequency or importance, so this cutoff can
strand a kanji's most important modern sense below the fold whenever KANJIDIC
happens to list it 5th or later. For 調, KANJIDIC2's real list (confirmed
against [kanjiapi.dev](https://kanjiapi.dev/), a public KANJIDIC2 mirror — no
need to fetch the full ~90MB dictionary) is:

```
tune, tone, meter, key (music), writing style, prepare, exorcise,
investigate, harmonize, mediate
```

"investigate" is 8th, so it never survives the `[:4]` cut.

## Methodology

1. Loaded every `KANJI_ENTRIES` array across all 18 `kanji-grade-*.js` files
   (grades 1–6, secondary-jōyō 8-1…8-6, beyond-jōyō 9-1…9-6) — **3,033 unique
   kanji** total.
2. Kept only entries whose stored `meanings` list is **exactly 4 long** —
   the signature of having hit the cap (a shorter list means KANJIDIC
   genuinely only had that many meanings, not a truncation). **1,208
   candidates.**
3. Queried kanjiapi.dev for each candidate's real, untruncated meanings list.
   **711 of the 1,208 have more meanings beyond position 4** — i.e. real
   truncation happened. (0 lookup failures.)
4. A cut meaning isn't automatically a bug — many of the 711 are just extra
   near-synonyms of what's already listed, and the app doesn't need every
   kanji to list all 6-10 KANJIDIC senses. To find the ones that actually
   matter, each kanji's **own curated example words** (`words: [...]`,
   already stored and used elsewhere on the same detail screen) were checked
   for a word-stem match against a cut meaning that the stored meanings list
   doesn't already imply. This is exactly the 調 pattern: the example words
   pointed at a sense the meanings list never mentioned.
5. **128 kanji flagged** this way — cases where the app's own example words
   contradict its own meanings list. This is a heuristic (crude 6-character
   English word-stem overlap), not a certainty: worth a quick skim rather
   than trusting every row blindly, and it's a lower bound — some of the
   other 583 "just extra synonyms" cases may also be worth a second look
   later, just not surfaced by this pass.

## Standouts worth a first look

A few where the missing meaning is the kanji's single best-known sense, not
a nuance — same pattern as 調:

- **悪** (grade 3) — stored `bad, vice, rascal, false`, missing **evil**. The
  character's most basic gloss, and its own example words say "evil"
  outright.
- **中** (grade 1) — missing **center**, arguably 中's most-taught meaning in
  English ("centre, middle, in, inside" — "center" and "middle" are near
  synonyms, but a learner searching "center" would get nothing).
- **命** (grade 3) — stored `fate, command, decree, destiny`, missing
  **life** (命 as in 生命, 命がけ — extremely common).
- **行** (grade 2) — missing **bank** (行 alone, as in 銀行), a very common
  practical meaning distinct from "going/journey/conduct."
- **見** (grade 1) — missing **opinion** (見解, 意見 — a distinct sense from
  "see/hopes/chances").

## Recommended fix

Same shape as `OBSCURE_WORD_OVERRIDE` already in `build_kanji_data.py`: add
a small, hand-maintained override table (e.g. `MEANING_INCLUDE = {"調":
["investigate"], "悪": ["evil"], ...}`) consulted in `parse_kanjidic()` so an
override's meanings are guaranteed to survive the cut — by adding one extra
slot per override rather than dropping an existing meaning, so this doesn't
also need re-litigating what today's kept 4 should be. Then re-run
`tools/build_kanji_data.py` (needs `tools/fetch_kanji_sources.sh` first,
~90MB, not committed) and diff the output — expect changes confined to the
overridden kanji; anything else changing would mean EDRDG's dictionaries
moved since this data was last generated, which would need a look before
committing.

Not built yet — this file is the audit only. Full raw data (all 711
truncated kanji, not just the 128 flagged here) is in the session's
scratch output if useful, but wasn't included here to keep this file
reviewable.

## Open questions

- **Coverage**: only kanji whose stored list is exactly 4 long were checked.
  A kanji with fewer than 4 stored meanings was, by definition, not
  truncated by this bug — not re-verified here.
- **The 583 unflagged truncated kanji**: real cuts KANJIDIC made, but the
  word-stem heuristic found no own-example-word evidence they matter. Some
  may still be worth a second pass (e.g. with a different heuristic or a
  manual skim), but that's more effort for a much lower hit rate.
- **False positives**: a few flagged rows are borderline (e.g. 房 → "lock
  (hair)", 徹 → "sit up (all night)") — real per KANJIDIC, but arguably a
  nuance rather than a headline gap like 調/悪/中. Worth a skim before
  fixing all 128 verbatim.
